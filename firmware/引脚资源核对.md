# 引脚资源核对（STM32F103C8T6，中容量 MD / 48 脚 LQFP）

本工程使用的引脚与外设**互不冲突**。下表逐脚列出"本工程用途"与"该引脚的其它复用功能
（本工程全部避开）"。所有复用功能均使用**默认映射**，不做 AFIO 重映射，因此不会相互抢占。

| 引脚 | 本工程用途 | 配置 | 该引脚的其它复用功能（本工程都**不**使用） |
| --- | --- | --- | --- |
| **PA0** | ADC1_IN0，电位器滑端 / 外部 0~3.3 V 信号输入 | `GPIO_Mode_AIN` 模拟输入（断开数字输入电路） | `TIM2_CH1`、`WKUP`。本工程不初始化 TIM2、不使用待机唤醒；PA0 配成模拟输入后数字复用功能不再生效。 |
| **PA8** | TIM1_CH1，100 Hz 自检 PWM 输出（默认关闭） | `GPIO_Mode_AF_PP` 复用推挽 | `USART1_CK`、`MCO`。本工程 USART1 只作异步收发（PA9/PA10），不用同步时钟 CK，也不输出 MCO。 |
| **PA9** | USART1_TX（设备 -> 电脑） | `GPIO_Mode_AF_PP` 复用推挽 | `TIM1_CH2`。本工程 TIM1 只启用 CH1，不用 CH2。 |
| **PA10** | USART1_RX（电脑 -> 设备） | `GPIO_Mode_IPU` 上拉输入 | `TIM1_CH3`。本工程 TIM1 只启用 CH1，不用 CH3。 |
| **PB8** | OLED SCL，软件 I2C 时钟（bit-bang） | `GPIO_Mode_Out_OD` 开漏输出 | `TIM4_CH3`、I2C1 remap 的 SCL。本工程不初始化 TIM4、不启用硬件 I2C1 外设、不做 AFIO 重映射，纯 GPIO 翻转。 |
| **PB9** | OLED SDA，软件 I2C 数据（bit-bang） | `GPIO_Mode_Out_OD` 开漏输出 | `TIM4_CH4`、I2C1 remap 的 SDA。同上，未用 TIM4 / 硬件 I2C。 |

## 不占用引脚的内部资源

| 资源 | 用途 | 是否有引脚输出 |
| --- | --- | --- |
| **TIM3** | 仅用"更新事件 TRGO"作为 ADC1 规则组外部触发源 | **无**：TIM3 不输出任何引脚（其 CH1~CH4 在 PA6/PA7/PB0/PB1 或 PC6~PC9，本工程一个都不用），因此与 GPIO 分配完全不冲突。 |
| **DMA1_Channel1** | ADC1 转换结果搬到 `g_adc_buf[1024]` | 无引脚（ADC1 专用 DMA 通道）。 |
| **SysTick** | 1 ms 时基（OLED 刷新 / 串口超时） | 内核定时器，无引脚。 |
| **NVIC** | DMA1_Channel1 / USART1 / SysTick 中断优先级 | 内核，无引脚。 |

## 结论与要点

1. **互不冲突**：PA0(ADC) / PA8(TIM1_CH1) / PA9+PA10(USART1) / PB8+PB9(软件 I2C OLED)
   分属不同引脚；TIM3 只作内部触发、DMA/SysTick/NVIC 不占引脚。
2. **不需要 AFIO 重映射**：USART1 默认就在 PA9/PA10，TIM1_CH1 默认在 PA8，ADC1_IN0 默认
   在 PA0；OLED 用普通 GPIO 软件模拟 I2C，不占用硬件 I2C 外设。工程里开 AFIO 时钟仅为
   标准库例程习惯，不启用任何重映射。
3. **被明确避开的复用功能**：PA0 的 `TIM2_CH1` / `WKUP`、PA8 的 `USART1_CK` / `MCO`、
   PA9/PA10 的 `TIM1_CH2/CH3`、PB8/PB9 的 `TIM4_CH3/CH4` 与硬件 I2C1 remap，本工程全部不用。
4. **自检 PWM 与外部信号不可同时驱动 PA0**：PA8 输出经限流/滤波接回 PA0 做自检时，
   必须断开 PA0 上的外部输入，避免两个信号源同时灌入同一 ADC 输入。
5. **未实测项**：板上实际晶振、实际 3.3 V 电源电压、USB 转 TTL 模块电平与接线均需现场确认；
   本工程**不宣称板上 3.3 V 恰好等于 3.300 V**，也不把任何推测写成已实测硬件能力。
   逐针接线与上板验收步骤见 `docs/接线与硬件.md` / `docs/上板验收.md`（由文档 agent 负责）。

## 补充：采样率推导、触发源与工程模板遗留项（审查记录 R9）

### 采样率与 ADC 相容性
- TIM3 时钟 = **72 MHz**（APB1 预分频 2 → PCLK1 = 36 MHz；因 APB1 预分频不为 1，
  定时器时钟 = 2×PCLK1）。
- PSC = 0：
  - **10 kS/s（默认）**：72 MHz / 10000 = 7200 → `ARR = 7200 - 1 = 7199`（触发周期 100 µs）。
  - **100 kS/s（SET_RATE 可切）**：72 MHz / 100000 = 720 → `ARR = 720 - 1 = 719`（触发周期 10 µs）。
    100 kS/s 是设计目标，不是已上板实测指标；采样率不等于带宽。
- ADC 时钟：PCLK2 = 72 MHz，`RCC_PCLK2_Div6` → **ADCCLK = 12 MHz**（不得超过 14 MHz）。
- 一次转换 = 55.5（采样）+ 12.5（转换）= **68 cycles = 68 / 12 MHz = 5.667 µs**；
  100 kS/s 触发间隔 10 µs > 5.667 µs，转换能在下次触发前完成，相容；10 kS/s 的 100 µs 更宽松。
- 信号源阻抗：55.5 cycles 采样窗口对高阻信号源可能充不满采样电容，电位器滑端建议
  并联 0.1 µF 或加电压跟随器缓冲；源阻抗过大时即便 55.5 cycles 也不够，属后续扩展。

### 外部触发源选择（核对 F103，不照搬其他系列）
核对 `Library/stm32f10x_adc.h`（第 123~131 行）与 STM32F103 中容量参考手册：ADC1/ADC2
规则组外部触发只有 `T1_CC1 / T1_CC2 / T2_CC2 / T3_TRGO / T4_CC4 /
Ext_IT11_TIM8_TRGO / T1_CC3 / None`，**没有 TIM2_TRGO、没有 TIM8_TRGO**（TIM8_TRGO 属
ADC3 或别的系列）。因此本工程选 **`ADC_ExternalTrigConv_T3_TRGO`** +
`TIM_SelectOutputTrigger(TIM3, TIM_TRGOSource_Update)`（`0x0020`，已在
`stm32f10x_tim.h` 第 913 行确认存在）。这是核对 F103 库头文件/参考手册后的选择，
不是照搬其他系列。TIM3 只作内部 TRGO，不引出任何引脚。

### 工程模板遗留项（避免误读为硬件事实）
- **`<Cpu> ... CLOCK(12000000) ... </Cpu>` 中的 `CLOCK(12000000)` 是 Keil 调试/仿真的核心
  时钟参数，不是外部晶振频率**，不能当作 HSE 证据。真正的 `HSE_VALUE = 8000000`（8 MHz）
  在 `Start/stm32f10x.h` 的 MD 分支；SYSCLK = 72 MHz 由 `Start/system_stm32f10x.c` 的
  `SYSCLK_FREQ_72MHz` 决定。**开发板实际晶振与实际电源电压仍需用户现场确认**。
- **`<FlashDriverDll>...STM32F10x_128.FLM...</FlashDriverDll>` / `<FlashUtilSpec>` 中的
  "128" 是从参考工程模板继承的 Keil 烧录算法名**（Flash 编程算法文件名），与
  STM32F103C8 的 64 KB Flash / `IROM 0x08000000,0x10000` **不矛盾**：仅影响 Keil 下载时
  选用哪个算法，**不影响编译、链接与 HEX 内容**；本机命令行构建不涉及它，
  **实际烧录需用户在 Keil 中确认/选择正确的 64 KB 器件算法**。
