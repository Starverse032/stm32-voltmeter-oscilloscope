## 1. 第一版能测什么、不能测什么

- 能测：**相对开发板 GND 的 0～3.3 V 直流或缓慢变化信号**，单通道，从 PA0 进入。【设计推导 / 协议规定，见 `docs/protocol.md` 第 1 节】
- 第一版**不依赖**外置 ADC、运放、BNC 探头、额外屏幕，只用一块最小系统板 + 电位器 + 4 针 OLED。【文件核对：任务书第 5 节】
- **不能测**：超过 3.3 V 的电压、负电压、交流的负半周、市电、任何高压。接错会**永久损坏芯片**。【设计推导】
- 它**不是通用示波器**，没有过压保护、没有衰减档位、没有抗混叠滤波、没有隔离。【设计推导】

### 2.2 电位器（第一版必接）

【文件核对】参考工程 `User/main.c` 顶部接线注释写的是"电位器两端接 3.3V 和 GND，中间脚（滑动端）→ PA0"；`Hardware/AD.c` 用的是 PA0 / ADC1 通道 0。

- 两端分别接 `3.3V` 和 `GND`，中间脚接 `PA0`。
- **为什么这样接**：电位器相当于一个可调分压器，滑动端电压在 0～3.3 V 之间连续变化，正好落在 ADC 能测的范围内，于是"拧旋钮"就得到一个已知来源、幅度安全的测试信号。
- 旋转方向对应电压升高还是降低，取决于哪一端接 3.3 V；接反只是方向反过来，不影响安全。【设计推导】

### 2.3 OLED（第一版必接）

【文件核对】`Hardware/OLED.c` 里 `OLED_W_SCL(x)` 操作 `GPIOB` 的 `GPIO_Pin_8`、`OLED_W_SDA(x)` 操作 `GPIO_Pin_9`，即 **SCL→PB8、SDA→PB9** 的软件 I2C；`User/main.c` 注释写 OLED `VCC → 3.3V，GND → GND`。

- 四根线：VCC、GND、SCL、SDA，一一对应，**不要接反 SCL/SDA**。
- **为什么用 3.3 V 供电**：板上逻辑电平是 3.3 V，用 3.3 V 最稳妥。有些 OLED 模块标称也支持 5 V，但那是模块自己的事，【待确认】你的模块是否支持、丝印怎么标；第一版一律按 3.3 V 接。
- 软件 I2C 用开漏输出（`GPIO_Mode_Out_OD`），依赖上拉电阻把总线拉高；【文件核对】参考工程没有额外使能上拉的代码，通常模块板上已带。若屏幕无显示，这是排查点之一（见 `docs/上板验收.md`）。

### 2.4 连电脑才需要：USB 转 TTL 模块（连电脑时必接）

【文件核对】`docs/protocol.md` 第 1 节规定 USART1，PA9 = TX（设备→电脑）、PA10 = RX（电脑→设备），115200 / 8N1 / 无流控。

- **交叉接**（这是最容易接错的一处）：
  - 模块 `TXD` → 设备 `PA10`（USART1_RX）
  - 模块 `RXD` → 设备 `PA9`（USART1_TX）
  - `GND` ↔ `GND`
- **为什么交叉**：一方的"发"要接另一方的"收"。模块丝印的 TXD/RXD 是站在**模块自己**的角度命名的，所以和设备正好反过来。
- **接反了会怎样**：通常只是收不到数据、界面一直"等待设备"，一般**不会烧芯片**；断电后把两根线对调即可。但**没断电就反复插拔**仍有短路风险，务必先断电。
- **逻辑电平必须是 3.3 V 兼容**【待确认：模块型号和跳线位置】：
  - 若模块 TXD 输出 5 V，第一版**不接受**。即使部分 STM32 引脚标称可容忍 5 V 输入，也存在两个真实风险：① 开发板**未上电时**，5 V 会经引脚内部钳位二极管**倒灌到 3.3 V 电源轨**，可能让板子异常上电甚至损坏；② 电平阈值不匹配会让串口误码。【设计推导】
  - 请用模块的 3.3 V / 5 V 跳线切到 **3.3 V**，或换 3.3 V 电平的模块。
- **必须共地**：ADC 测的是"相对板上 GND"的电压，串口电平也以 GND 为参考。不共地，通信会失败或乱码，电压概念也不成立。【设计推导 / 协议规定】
- **VCC 一般不要接**：开发板通常已由 USB 口或 ST-Link 供电。若模块 VCC 再接到板子 3.3 V，等于两个电源并联——两者输出电压只要有微小差异就会产生环流，可能损坏 LDO。【设计推导】
  - 只有当**明确由该模块单独给板子供电**、且已确认模块输出是 3.3 V、电流够、且板上没有其他电源时，才接 VCC。【待确认】

### 2.5 烧录才需要：ST-Link V2（SWD）

【文件核对】`C:\Users\29319\Desktop\STM32Project\AGENTS.md` 记录用户使用 "ST-Link V2 下载器，SWD 接线：SWDIO、SWCLK、GND、3.3V"。**这是文件记录，不是实物盘点**。

- 四线：`SWDIO`、`SWCLK`、`GND`、`3.3V`。板上找标着 SWDIO / SWCLK 的排针（【设计推导】通常对应 PA13 / PA14，以板上丝印为准，【待确认】你的板子丝印）。
- **3.3V 这一根要分情况**：
  - 板子已经通过 USB 供电：**只接 SWDIO / SWCLK / GND 三根即可**，ST-Link 的 3.3V 不接（避免两个电源并接）。
  - 需要 ST-Link 给板子供电：先确认该 3.3V 引脚是**输出**而非仅作参考电压、且电流够，并且板上没有其他电源。【待确认】
- 本项目**不会自动烧录**，烧录动作由用户按 `docs/上板验收.md` 执行。【文件核对：任务书第 6 节】

### 2.6 自检才需要：PA8 → 限流电阻 → PA0

【设计推导 / 协议第 4.2 节】自检 PWM 为 PA8（TIM1_CH1）输出的 100 Hz、0～3.3 V 方波，用来确认"链路能出波形"。

- 接法：`PA8` → **限流电阻** → `PA0`。
- **电阻取值建议：1 kΩ ～ 4.7 kΩ**（【设计推导】，见第 6 节的理由）。
- **PA0 与外部信号绝对不可以同时驱动**（本节最重要的一条，详见 2.7）。

### 2.7 ⚠️ PA0 同一时刻只能有一个驱动源

> **这是硬性安全规则，不是建议。**

`PA0` 是唯一的 ADC 输入。同一时刻它只能被**一个**信号源驱动：

- 要么接**电位器滑动端**（外部信号），
- 要么接**PA8 经限流电阻过来的自检 PWM**，
- **不能两者同时接，也不能"一边接电位器一边开自检 PWM"**。

**为什么**：
1. 两个输出源并联会互相"顶牛"：电位器把 PA0 拉到某个电压，PA8 又想把它拉到 0 或 3.3 V，最终电压由两者内阻分压决定，**读数不再是任何一个真实信号**，显示出来的曲线没有物理意义。
2. 若电位器恰好旋到端点（接近 0 V 或 3.3 V），而 PA8 正输出相反电平，会经限流电阻形成不小的电流；虽然电阻能限流，但这属于人为制造冲突，没必要冒这个险。【设计推导】
3. 自检的意义是"用一个已知信号验证链路"，若同时挂着一个未知的外部信号，就失去了验证意义。

**正确做法**：做自检时，**先断开电位器滑动端与 PA0 的连线**，再接 PA8→电阻→PA0；自检结束后断开 PA8 那路，再接回外部信号。每次切换都要**先断电**。

## 3. 首次测试步骤（从最少接线开始，逐步加）

> 原则：**一次只加一样东西**，每加一样都先确认上一步正常。
> 每一步都写了「预期现象」和「看到什么就立刻断电」。所有"预期现象"都是【设计预期 / 未实测】，不是已发生的事实。

### 步骤 0：完全不上电，先做静态检查

- 断开所有电源（拔掉 USB、ST-Link、USB-TTL）。
- 目视：确认没有线头搭到相邻引脚、没有 5V 线接到 PA0、杜邦线金属头没有裸露相碰。
- 若有万用表：量 `3.3V` 与 `GND` 之间**不应短路**；量电位器滑动端在两端点时对 GND 的电压应分别接近 0 V 和 3.3 V（此时未上电，量的是电阻关系，可先只确认不短路）。
- **预期现象**：无明显短路、无接错线。
- **立刻断电 / 不要上电的情况**：发现 PA0 上接着任何可能的 5 V / 市电 / 外部高压线；发现 VCC 与 GND 疑似短接；闻到焦味或看到元器件发烫（说明之前可能已上电）。

### 步骤 1：只接 OLED + 电位器，上电

- 按 2.2 / 2.3 接好 **6 根线**（电位器 3 根 + OLED 4 根，其中 GND 共用）。**此时不接 USB-TTL、不接电脑、不接自检 PWM**。
- 给板子上电（USB 或 ST-Link 供电，二选一）。
- **预期现象**【设计预期 / 未实测】：OLED 点亮并显示电压数值；缓慢旋转电位器，数值在约 0～3.3 V 之间平滑变化；**没有电脑连接也能独立当电压表用**。
- **立刻断电**：冒烟 / 异味 / 芯片或 OLED 发烫；OLED 不亮但板子明显发热；上电瞬间电脑提示 USB 异常。
- 若 OLED 无显示：先别急着改代码，按 `docs/上板验收.md` 的"OLED 无显示"排查清单逐项查（供电、SCL/SDA 是否接反、程序是否烧录成功）。

### 步骤 2：确认"不接电脑也能工作"

- 保持步骤 1 的接线，故意不连串口。
- **预期现象**【设计预期】：OLED 持续刷新电压读数，程序没有卡在"等待电脑握手"。
- **为什么强调这点**：协议规定设备上电后独立完成 ADC/OLED 初始化并按默认状态运行，串口只是附加控制通道，不能因为没有电脑就死等。【文件核对：`docs/protocol.md` 第 4.2 节】

### 步骤 3：需要烧录固件时，断电接 ST-Link

- **先断电**，按 2.5 接 SWD 四线（或三线，见 2.5 的供电说明），烧录 `firmware/Objects/Project.hex`（具体路径以 `firmware/README.md` 为准）。
- 烧完**断电**，拔掉 ST-Link，再单独上电回到步骤 1 的状态。
- **预期现象**【设计预期】：重新上电后行为与步骤 1 一致。
- **立刻断电**：烧录时芯片发烫、ST-Link 报错且板子异常发热。
- 【未实测】本次工作没有执行过任何烧录。

### 步骤 4：电脑端先跑「模拟模式」，不接真实设备

- 保持开发板**不通过串口连电脑**（可以完全不给板子上电，或只上电但不接 USB-TTL）。
- 双击 `outputs/安装依赖.bat` 装好依赖，再双击 `outputs/启动仪器.bat`。
- 在界面选择 / 确认处于**「模拟数据」**模式。
- **预期现象**【设计预期 / 未实测】：窗口能打开，界面**显著标注"模拟数据"**；切换"电压表 / 示波器"视图；波形可切正弦 / 方波 / 直流；运行、暂停、单次、缩放、CSV 导出都能操作。
- **此时屏幕上任何波形都不是真实测量**，仅用于确认软件本身没问题。
- **这一步不需要"断电"判断**（没接硬件），但若程序报错打不开，先把 Traceback 原文保存下来排查。

### 步骤 5：断电，接 USB-TTL

- **先给板子断电**，按 2.4 接好 4 根线（TXD / RXD / GND，VCC 通常不接），确认模块是 **3.3 V 逻辑**、已共地。
- 上电，把 USB-TTL 插到电脑。
- **预期现象**【设计预期】：电脑设备管理器里出现一个串口（COMx）；板子 OLED 仍正常显示。
- **立刻断电**：插上 USB 后板子发烫、电脑提示 USB 设备异常 / 端口反复掉线、闻到异味。
- 【待确认】PC 上是否有可用的串口驱动、模块具体型号。

### 步骤 6：连接真实串口，拿到第一条真实曲线

- 在界面点「刷新」枚举端口，选中对应 COM 口，点「连接」，确认状态栏显示**真实设备**（不是"模拟数据"）。
- 点「运行」。
- **预期现象**【设计预期 / 未实测】：出现电压—时间曲线；缓慢旋转电位器，曲线整体上下移动；静止时接近一条水平线；电压表视图给出平均 / 最小 / 最大 / 峰峰值。
- **立刻断电**：PA0 上量到超过 3.3 V 或负电压；板子或模块发热。
- 若"波形是一条直线""读数贴 0 或贴 4095""帧不更新"，按 `docs/上板验收.md` 对应条目排查。

### 步骤 7：切换到自检 PWM（注意互斥）

- **先断电**，按 2.7 **断开电位器滑动端**，接 `PA8 → 限流电阻 → PA0`。
- 上电后，需通过协议命令 `CMD_SELFTEST_PWM (0x07)` 开启自检 PWM；当前 GUI 没有此开关。开启方式和限制见 [使用教程第 6 节](使用教程.md#6-触发周期波形与自检的范围)。再在电脑端选上升沿触发并调阈值。
- **预期现象**【设计预期 / 未实测】：出现约 100 Hz 的方波并稳定对齐。
- **立刻断电 / 不要这样操作**：发现电位器滑动端还挂在 PA0 上却开了自检 PWM（两个源同时驱动）。

### 步骤 8：切换采样率、触发、导出 CSV

## 5. 输入边界与风险（务必逐条读完）

1. **PA0 只能测相对板上 GND 的 0～3.3 V。**【文件核对：任务书第 5 节 + 协议第 1 节】
2. **绝不能接 5 V、负电压、交流负半周、市电。** 超过 3.3 V 或低于 0 V 都可能经引脚内部钳位二极管灌入电源轨，**永久损坏芯片**。【设计推导】
3. **"开发板有 5V 引脚" ≠ "ADC 能测 5V"。** 5V 引脚只是供电/给外部模块用的电源输出，和 ADC 输入范围完全是两回事。把 5V 接到 PA0 是最典型的烧板方式。【设计推导】
4. **悬空 ADC 读数不代表 0 V。** PA0 什么都不接时，引脚浮空，输入电容上的电荷不确定，读数会随机漂移。想确认"0 V"，必须把 PA0 **明确接到 GND**；界面上那个跳动的数字在浮空时没有物理意义。【设计推导】
5. **USB 转 TTL 逻辑电平必须兼容 3.3 V。** 5V TX 的风险见 2.4（未上电倒灌 + 电平阈值误码）。【待确认 + 设计推导】
6. **USB 接电脑后必须共地**（模块 GND ↔ 板 GND）。不共地，串口没有共同参考电平，且"相对板上 GND 的电压"这个概念也不成立。【设计推导 / 协议规定】
7. **独立供电时不要随意并接两个 VCC。** 两个 3.3 V 电源并联会因微小压差产生环流。只保留一个供电源，其余只接 GND 和信号线。【设计推导】
8. **外部信号源也必须与板共地。** 否则 ADC 测到的电位差可能包含两个地之间的未知电压，读数无意义甚至引入高压。【设计推导】
9. **任何接线改动都要先断电。** 带电插拔容易让线头瞬间搭到相邻引脚造成短路。【设计推导】

## 6. 自检信号（PA8 的 100 Hz PWM）说明

- 【设计推导 / 协议第 4.2 节】PA8（TIM1_CH1）输出约 100 Hz、0～3.3 V 的 PWM，经限流电阻接 PA0，作为**已知来源**的自检波形。
- **它只能证明"链路能出波形"**：ADC 在采、DMA 在搬、串口在发、电脑能画、触发能对齐。
- **它不能证明**：
  - **高速带宽**（100 Hz 是极低频，看不出 100 kS/s 下前端的真实频率响应）；
  - **绝对精度**（方波幅度由 PA8 的 3.3 V 电平决定，而 3.3 V 本身未必是 3.300 V，见第 8 节）。
- **限流电阻取值 1 kΩ ～ 4.7 kΩ 的理由**【设计推导】：
  - ADC 输入是高阻，理论上不串电阻也能工作；串电阻是为了在**误配置**（例如 PA0 被错配成输出、或两路信号误接）时限制电流，起隔离作用。
  - 不能取太大：F103 的 ADC 内部有采样电容，外部源阻抗越大，采样电容在采样时间内越充不满，读数会偏低。【文件核对】参考工程 `Hardware/AD.c` 选了 **55.5 cycles** 采样时间，正是为较高源阻抗留余量；一旦把电阻取到几十 kΩ 以上，就需要重新核对数据手册里"采样时间 ↔ 最大源阻抗（RAIN）"的关系。【待查手册 / 设计推导】
  - 1 kΩ ～ 4.7 kΩ 是保守且常见的取值，兼顾隔离与采样电容充电。
  - **⚠️ 这个电阻不是"过压保护"**：它只能限流，**不能把 5 V 变成 3.3 V**。PA0 的安全靠的是"根本不接超过 3.3 V 的信号"，不是靠这颗电阻。【设计推导】
- **与外部信号互斥**：见 2.7，同一时刻 PA0 只能有一个驱动源。

### 7.2 若以后想扩大量程：一个"分压例子"以及它必须核对的四件事

> 这一节是**后续扩展的思路，不是第一版可照做的电路**，也**未实测**。初学者第一版请**不要**接任何分压器去测高压。

概念性例子【设计推导，仅用于说明要算什么】：假设想把 0～10 V 降到 ADC 的 0～3.3 V 以内，会用"上拉电阻 R1 + 下拉电阻 R2"分压，`V_ADC = V_in × R2/(R1+R2)`。例如取 R1=22 kΩ、R2=10 kΩ，10 V 输入时 `V_ADC = 10 × 10/32 ≈ 3.125 V`，留了约 5% 余量。但这**远远不够**，必须逐项核对：

1. **余量**：被测最大值 × 分压比必须明显小于 3.3 V（留 10～20% 以上），并考虑电阻误差、3.3 V 轨波动、信号过冲、以及误接更高电压的可能。上例 3.125 V 只留了很小余量，工程上还要再加保护。
2. **误差**：电阻精度（1% / 5%）、温漂、ADC 自身误差、`vref_mv` 误差会一起叠加；分压比越大，误差被放大得越明显。【设计推导】
3. **ADC 源阻抗**：分压器的戴维南等效阻抗是 `R1 // R2`（上例约 6.9 kΩ），必须满足 F103 在所选采样时间下允许的最大源阻抗，否则采样电容充不满、读数偏低；必要时加**电压跟随器（运放缓冲）**，而运放又要考虑其带宽、压摆率、输入共模范围与供电。【设计推导 / 待查数据手册】
4. **保护**：分压器**本身不提供任何过压保护、隔离或负电压处理**。仍需串联电阻、钳位二极管 / TVS、以及针对负半周的偏置与限幅电路；交流负半周要把信号中点抬到约 1.65 V 再限幅，又是另一套设计。【设计推导】

> **必须写清楚的一句话：一个分压器不是完整的通用示波器前端。** 真正的通用前端还需要衰减档位切换、过压保护、输入阻抗匹配、AC/DC 耦合、抗混叠低通滤波、带宽限制、以及电气隔离；这些都不在本项目范围内。【设计推导】

## 8. 概念澄清（初学者最容易混淆的几件事）

### 8.1 参考电压影响精度：`V = code / 4095 × vref`

- 【文件核对：`docs/protocol.md` 第 4.1 节】12 位 ADC 右对齐，码值 0～4095；电压换算统一为 `V = code / 4095.0 × (vref_mv / 1000.0)`。
- **参考电压（`vref`）不是"想当然的 3.300 V"**：F103 的 ADC 参考通常来自 `VDDA`（板上 3.3 V 轨），而 LDO 输出可能是 3.28 V 或 3.31 V。**默认 `vref_mv = 3300` 只是名义值，不是精确值**。【设计推导 / 待确认：实际电源电压】
- **所以**：想要更准，需要用万用表实测板上 3.3 V 轨，通过协议的 `SET_VREF`（0x05，允许 2500～3600 mV）把实测值告诉设备；该值**只改设备本次运行，掉电不保存**。【文件核对：协议第 4.1 / 4.2 节】
- **OLED 与电脑必须用同一把尺子**：协议规定 `vref_mv` 随采样帧上报，设备 OLED 和电脑端都用同一个 `vref_mv` 换算，电脑端**不得自行假定 3.300 V**，也不允许出现"OLED 一个数、电脑另一个数"却没人告诉你。【文件核对：协议第 4.1 节 + 第 9 节】
- 显示位数（例如 1.6504 V）只是数学换算结果，**不冒充测量精度**。【文件核对：任务书第 4 节】

### 8.2 采样率 ≠ 带宽

- **采样率**是"每秒采多少个点"（本项目设计目标 10 kS/s 和 100 kS/s）；**带宽**是"能不失真测到的最高信号频率"。两者不是一回事。【设计推导】
- 奈奎斯特准则告诉我们采样率至少要是信号频率的 2 倍，实际要看清波形通常要 5～10 倍以上；100 kS/s 实际能"看清楚"的也就几 kHz～十几 kHz 量级，而且高频分量会衰减。【设计推导】
- 还受这些因素限制：**采样时间 / 源阻抗**（采样电容能否在窗口内充满，见 6 节）、**前端模拟带宽**、**混叠**（没有抗混叠滤波时，高于采样率一半的频率会折返成假的"低频"信号，你以为测到了，其实是假的）。【设计推导】
- 本项目**没有抗混叠滤波**，所以高频信号出现"莫名低频波形"是预期内的现象，不是设备故障。【设计推导】

### 8.3 采集帧率 / 采样率 ≠ 屏幕刷新率

- ADC 按 10 µs（100 kS/s）或 100 µs（10 kS/s）等间隔采点，但**屏幕可能每几百毫秒才刷新一次**，你看到的是"一帧一帧"的静态画面，不是连续实时视频。【设计推导】
- 同理，OLED 用较低刷新率显示平均 / 最小 / 最大值，**它的刷新不能打断一帧内的等间隔采样**。【文件核对：任务书第 4 节固件要求】

### 8.4 为什么 115200 串口不能连续无损传 100 kS/s

- 100 kS/s 的 uint16 流 = 100000 × 2 B/s = **200 kB/s**。【设计推导】
- 115200 8N1 每字节约 10 位（1 起始 + 8 数据 + 1 停止），有效约 **11520 B/s**。【文件核对：协议第 1 节给出约 11520 B/s】
- 差了约 **17 倍**，所以**不可能连续实时传输**。
- 因此第一版采用「**采集一帧（1024 点）→ 停止采样 → 发送这一帧 → 再采下一帧**」，**帧与帧之间有空隙**。一帧 1024 点约 2070 字节，传输约 180 ms。【文件核对：协议第 1 节 + 任务书第 4 节】
- **这个空隙不能藏起来**：时间轴每帧从 0 重新开始，CSV 带 `frame_seq` 且文件头注明"帧间不连续，时间轴为帧内相对时间"。【文件核对：协议第 4.1 / 9 节】把多帧首尾相连画成"连续采样"是错误的。
