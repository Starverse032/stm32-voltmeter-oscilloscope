# 上板验收流程（用户可照着做）

> 本文是**给用户的操作清单**：从拆包检查到导出第一条真实 CSV，每一步都写清「怎么做 / 什么算通过 / 不通过怎么排查」。
> 配套的接线细节与安全边界见 `docs/接线与硬件.md`，协议细节见 `docs/protocol.md`。
>
> **⚠️ 本文所有"通过判据"都是"你要看到什么才算通过"，不是"已经通过"。截至本文编写，本项目没有在真实硬件上执行过任何一步。**

---

## 0. 先分清三种完全不同的"成功"

这是最容易出问题的地方，请一定先读懂：

| 说法 | 到底证明了什么 | 不能证明什么 |
| --- | --- | --- |
| **能编译 / 生成了 HEX** | C 代码语法与链接没问题，Keil 能产出可烧录文件 | 不能证明 HEX 行为正确、不能证明能烧进芯片、不能证明 ADC 时序对、不能证明能出波形 |
| **能启动 GUI / 模拟模式跑通** | 电脑端软件本身能运行、界面交互没问题 | 不能证明串口、固件、接线、采样任何一项正常——**模拟数据是软件生成的，与硬件无关** |
| **上板通过** | 接线 → 烧录 → OLED → 串口 → 真实曲线 → 采样率 → 触发 → 导出，每一步都有**真实硬件上的实测现象** | —— |

> **"能编译""能启动 GUI""上板通过"三者证据等级完全不同，不能互相替代。**
> 【文件核对：任务书第 6 节】明确要求"静态检查或导入成功不等于 GUI 交互验证""没有工具则明确未构建，不得声称上板通过""不编造测量结果"。

本文沿用 `docs/接线与硬件.md` 的四类口径：

| 标签 | 含义 |
| --- | --- |
| 【文件核对】 | 已从本机文件核对的事实（只是文件这么写） |
| 【设计推导】 | 由协议 / 原理推出的"应该如此" |
| 【待确认】 | 需要你现场看实物 / 万用表 / 设备管理器确认 |
| 【未实测】 | 本次工作没在真板上跑过 |

## 1. 验收前准备

### 1.1 需要先确认的「待确认」项

在动手前，逐项打勾；**任何一项没确认，相关环节只能停在"未验证"**：

- [ ] 手上有 STM32F103C8T6 最小系统板，且板子完好。【依据 `AGENTS.md` / `Project.uvprojx` 的文件记录，**非实物盘点**】
- [ ] 手上有 4 针 I2C OLED，且能点亮。【待确认】
- [ ] 手上有电位器与足够杜邦线。【待确认】
- [ ] **有 USB 转 TTL 模块吗？型号是什么？逻辑电平是 3.3 V 还是 5 V？**【待确认，任务书明确说"历史上做过串口，模块是否仍在、型号需检查"】
- [ ] 开发板晶振频率（看板上晶振丝印，常见 8 MHz）。【待确认】
- [ ] 板上 3.3 V 轨实际电压（万用表量 3.3V↔GND）。【待确认】
- [ ] PC 有可用串口驱动、能识别 COM 口。【待确认】
- [ ] ST-Link V2 可用，其 3.3 V 引脚是输出还是参考电压已弄清。【待确认】
- [ ] Python 3.10+ 可用，`outputs/安装依赖.bat` 已成功执行（保留 pip 原始输出）。【待确认】

### 1.2 先核对交付物是否真的存在

**不要假设文件已经生成**。在文件管理器里确认：

- [ ] `firmware/Project.uvprojx` 存在（Keil 工程）
- [ ] `firmware/Objects/Project.hex` 存在，**且** `firmware/Objects/build.log` 显示构建成功
- [ ] `desktop/main.py` 存在
- [ ] `outputs/启动仪器.bat`、`outputs/安装依赖.bat`、`outputs/运行验证.bat` 存在
- [ ] `outputs/验证报告.md` 存在，并**读一遍本次真实构建/测试结果**

> 【文件核对 / 待确认】上面这句清单描述的是**编写时刻的快照**（当时 `firmware/` 为空、`desktop/` 仅有 `requirements.txt` 与安装日志）。多人协作期间文件持续增加，**最终交付状态一律以 `outputs/验证报告.md` 和本文末尾「14. 后续状态更新」为准**，不要用这句历史快照判断当前进度。
> 无论目录里出现了多少文件，**能否进入烧录与联机环节只看两件事**：`firmware/Objects/Project.hex` 是否已生成、`firmware/Objects/build.log` 是否为 `0 Error(s)`。任一项不满足，就回到「未实测」，不要烧录、不要联机。

## 2. 阶段 A：接线复核（**全程断电**）

### 操作
1. 拔掉所有电源：USB 线、ST-Link、USB-TTL 全部断开。
2. 按 `docs/接线与硬件.md` 第 2 节总表接线。第一版最小系统只接 **电位器（3 根）+ OLED（4 根）**，暂不接 USB-TTL、不接自检 PWM。
3. 目视检查：无 5 V 线接到 PA0、无线头搭到相邻引脚、无裸线相碰。
4. 万用表量 `3.3V` ↔ `GND` 不短路。

### 通过判据
- 接线与总表逐针一致；PA0 上只有电位器滑动端；3.3V 与 GND 不短路。【设计预期】

### 失败排查
- 发现 PA0 上接着 5 V / 市电 / 外部高压线 → **不要上电**，先改线。
- 3.3V 与 GND 疑似短路 → 逐根拔线定位，不要上电。
- 不确定某根线 → 对照 `docs/接线与硬件.md` 第 2.6 / 2.7 节，尤其 **PA0 不可同时接两个信号源**。

## 3. 阶段 B：构建并烧录固件

> 两条路径二选一。**"工程文件存在"不等于"编译成功"，必须看构建日志的退出码与是否有 Error。**

### B1. 路径一（推荐，可复现）：自己用 Keil 构建

在 `firmware/` 目录内用 PowerShell 执行【文件核对：`AGENTS.md` 第 19–28 行、`README.md` 第 116–121 行】：

```powershell
$p = Start-Process C:\Keil_v5\UV4\UV4.exe -ArgumentList '-b','Project.uvprojx','-j0','-o','Objects\build.log' -WorkingDirectory . -Wait -PassThru
Get-Content Objects\build.log; $p.ExitCode
```

也可双击 / 运行 `firmware/build.ps1`（若存在）。退出码：**0 = 成功，1 = 有警告，2 及以上 = 有错误**。

- 用 Keil 图形界面打开 `firmware/Project.uvprojx` 时，确认：`Device = STM32F103C8`、启动文件 `startup_stm32f10x_md.s`、IRAM 0x5000 / IROM 0x10000、已勾选 **Create HEX File**。【文件核对：`Project.uvprojx` 与 `交付自检.py` 的检查项】

#### 通过判据
- 退出码为 0（或 1 且确认警告可接受）；`build.log` 无 `Error`；出现 `Program Size: Code / RO-data / RW-data / ZI-data`；生成 `firmware/Objects/Project.hex`。【设计预期】

#### 失败排查
- 退出码 ≥ 2 或日志有 `Error(s)`：把 `Objects/build.log` 原文保存，按第一条报错定位（常见：新建 .c 未加入 Keil 分组、Include Paths 缺 `.\Common` / `.\Hardware`、启动文件型号不匹配）。
- 提示找不到 `UV4.exe`：确认本机 Keil 安装路径，把命令里的路径换成实际路径。
- 只有 `.axf` 没有 `.hex`：在 Keil → Options for Target → Output 勾选 **Create HEX File** 后重新构建。
- **若 `firmware/Project.uvprojx` 根本不存在**：固件尚未完成，本阶段记为「未执行」。

### B2. 路径二：使用交付包里已生成的 HEX

仅当以下条件**全部满足**才可直接烧录：
- `firmware/Objects/Project.hex` 存在；
- `firmware/Objects/build.log` 存在且显示构建成功（退出码 0 / 无 Error）；
- `outputs/验证报告.md` 里记录的构建结果与之一致。

> **不要只因为"有个 .hex 文件"就认为编译成功**——文件可能是旧的或占位文件。

### B3. 烧录到芯片（ST-Link V2，SWD）

1. **先断电**，按 `docs/接线与硬件.md` 第 2.5 节接 SWD（SWDIO / SWCLK / GND，3.3V 视供电方式决定）。
2. 用 Keil 的下载（`UV4.exe -f`）或 ST-LINK Utility 烧录 `firmware/Objects/Project.hex`。
3. 烧完**断电**，拔掉 ST-Link。

#### 通过判据
- 烧录工具报告校验通过、无错误；重新上电后进入阶段 C 有预期现象。【设计预期】

#### 失败排查
- 找不到芯片 / SWD 无响应：检查 SWDIO/SWCLK 是否接反、GND 是否共地、板子是否真的上电、是否被别的调试器占用。
- 烧录时芯片发烫 → **立刻断电**。
- 校验失败：重新断电再试，确认 HEX 与芯片型号匹配。

> 【未实测】本次工作**没有执行过任何构建或烧录**。上述命令与判据是给你照做的，不代表已跑过。

## 4. 阶段 C：上电看 OLED（**不接电脑**）

### 操作
保持阶段 A 的最小接线，单独给板子上电（USB 或 ST-Link 供电，二选一）。**故意不连串口、不连电脑**。

### 通过判据
- OLED 点亮并显示电压数值；
- 缓慢旋转电位器，数值在约 0～3.3 V 之间平滑变化；
- **没有电脑连接也能持续刷新**（程序没有卡在"等待握手"）。【文件核对：`docs/protocol.md` 第 4.2 节规定上电独立运行】

### 失败排查
- **OLED 无显示**：见第 11 节速查表。
- 数值不随电位器变化：检查滑动端是否真接到 PA0、两端是否接 3.3V/GND、电位器是否完好。
- 数值贴 0 或贴 4095：见第 11 节；**若贴 4095 且不是故意旋到端点，立刻断电并量 PA0 电压**。
- 上电后毫无反应：确认 HEX 已烧录成功、供电正常、复位后重试。
- **立刻断电**：冒烟 / 异味 / 芯片或 OLED 发烫 / 上电瞬间电脑提示 USB 异常。

## 5. 阶段 D：电脑端启动 + 模拟模式自检

### 操作
1. 双击 `outputs/安装依赖.bat`（首次），保留 pip 原始输出。
2. 双击 `outputs/启动仪器.bat` 启动窗口。
3. 确认界面**显著标注「模拟数据」**。此时**不接真实设备**（可以完全不给板子上电，或只上电但不接 USB-TTL）。
4. 依次点一遍：切换「电压表 / 示波器」视图、模拟源切正弦 / 方波 / 直流、运行、暂停、单次、滚轮缩放、复位视图、CSV 导出。

### 通过判据
- 窗口能打开、无 Traceback；界面明确写「模拟数据」，不会让你误以为在测量；
- 上述每个按钮都有可见响应；
- 模拟源能给出接近量程上下限、无触发、断线等可验证场景；
- 关闭窗口能干净退出（不残留串口 / 线程）。【文件核对：任务书第 4 节 + 协议第 9 节】

### 失败排查
- 打不开 / 报 Traceback：把**原始输出**保存下来；常见为 `.venv` 未创建、依赖没装全、PySide6 / pyqtgraph 版本问题。重跑 `outputs/安装依赖.bat`，对照 `desktop/tests/PIP_INSTALL.txt`。
- 界面没有「模拟数据」标注：**这是严重问题**，不要继续，先把状态标识修好（避免误认真实测量）。
- 某个按钮无响应：记下按钮名和现象，交给电脑端所有者。

> 提醒：**这一阶段的所有波形都是软件生成的，不是真实测量。** 它只证明"电脑软件本身能跑"。

## 6. 阶段 E：连接真实串口

### 操作
1. **先断电**，按 `docs/接线与硬件.md` 第 2.4 节接 USB-TTL：模块 `TXD`→`PA10`、模块 `RXD`→`PA9`、`GND`↔`GND`，VCC 通常不接；确认模块是 **3.3 V 逻辑**。
2. 上电，把 USB-TTL 插到电脑。
3. 在界面点「刷新」枚举端口，选中 COM 口，点「连接」。

### 通过判据
- Windows 设备管理器出现一个串口（COMx）；
- 界面状态栏显示**「真实设备」**（不是「模拟数据」/「已断开」/「等待设备」）；
- OLED 仍正常显示。【设计预期】

### 失败排查
- **串口找不到 / 下拉框是空的**：见第 11 节速查表（驱动、线缆、占用、刷新、3.3V 跳线）。
- 连上了但立刻「已断开」：检查 GND 是否共地、TX/RX 是否接反、波特率是否为 115200 8N1、是否有别的程序占着这个 COM 口。
- 状态栏一直「等待设备」：多为 TX/RX 接反（设备收不到命令也没法回响应），断电后把两根线对调。

## 7. 阶段 F：第一条真实曲线

### 操作
点「运行」，缓慢旋转电位器，观察示波器视图与电压表视图。

### 通过判据
- 出现电压—时间曲线，横轴按设备上报采样率换算成秒 / 毫秒，纵轴为伏特；
- 旋转电位器时曲线整体上下移动；静止时接近一条水平线；
- 电压表视图给出平均 / 最小 / 最大 / 峰峰值；
- 界面显示采样率、帧长度和数据状态。【文件核对：任务书第 4 节 + 协议第 4.1 节】

### 失败排查
- **波形是一条直线**：见第 11 节。
- **读数贴 0 或贴 4095**：见第 11 节（**贴 4095 且非故意 → 立刻断电查 PA0 是否误接 5 V**）。
- **帧不更新**：见第 11 节。
- 横轴明显不对：确认界面用的是**设备回读的 `sample_rate_hz`**，不是电脑自己猜的值。

## 8. 阶段 G：切换 10 kS/s ↔ 100 kS/s

### 操作
在界面把采样率从 10 kS/s 切到 100 kS/s，再切回来，各观察一段时间。

### 通过判据
- 切换时界面显示「切换中」；
- **只有**收到匹配 SEQ + `status=0x00` + `actual_rate_hz == 请求值` 的响应帧，才更新横轴与"采样率"标签；
- 采样帧里的 `sample_rate_hz` 与界面一致；
- 若在发送中切换，界面明确提示「设备忙，未切换」并保持旧状态，不静默假装成功。【文件核对：`docs/protocol.md` 第 2.1 / 4.2 / 4.3 / 9 节】

### 失败排查
- 只改了横轴、设备其实没切：这是**严重问题**（虚假显示），交给电脑端所有者核对响应帧处理。
- 一直「设备忙」：等当前帧发完再切，或先点「停止」。
- 切换后波形异常 / 帧不更新：先切回 10 kS/s 看是否恢复；记录现象，留意 100 kS/s 下前端源阻抗与混叠的影响（见 `docs/接线与硬件.md` 第 8 节）。

> 【未实测】10 kS/s / 100 kS/s 的**实际生效采样率与 100 kS/s 波形质量均未实测**；100 kS/s 是设计目标。

## 9. 阶段 H：触发

### 操作
1. 若要看周期性波形：先断电，按 `docs/接线与硬件.md` 第 2.6 / 2.7 节**断开电位器滑动端**，改接 `PA8 → 限流电阻 → PA0`。上电后需通过协议命令 `CMD_SELFTEST_PWM (0x07)` 开启自检 PWM，当前 GUI 没有启用按钮，详见 [使用教程第 6 节](使用教程.md#6-触发周期波形与自检的范围)。
2. 在界面选「上升沿触发」，调阈值，观察波形是否稳定对齐。
3. 再切回「自动」显示做对比。

### 通过判据
- 上升沿触发时波形稳定对齐；
- 未找到触发点时显示「等待触发 / 未触发」，**不伪造不存在的预触发数据**；
- 暂停或单次冻结后，后台新帧**不覆盖**当前画面。【文件核对：任务书第 4 节 + 协议第 9 节】

### 失败排查
- 一直「等待触发」：阈值是否超出信号幅度范围？信号是否真有上升沿？直流信号**本来就不该触发**（这是正常情况，不是故障）。
- 波形不对齐：确认用的是自检 PWM（频率约 100 Hz）而非电位器直流；确认 PA0 上没有同时挂两个信号源。
- 冻结后画面还在变：交给电脑端所有者核对暂停 / 单次状态机。

> 【未实测】真实信号上的触发稳定性未实测。

---

## 10. 阶段 I：CSV 导出

### 操作
点「导出 CSV」，打开生成的文件检查内容。

### 通过判据
- 文件存在且能打开；
- 至少包含：本帧时间、原始 ADC 码、换算电压；
- 文件头 / 元数据含采样率、`vref_mv`、帧序号 `frame_seq`；
- 明确注明「帧间不连续，时间轴为帧内相对时间」，**没有把帧间空隙伪装成连续采样**；
- 每帧时间轴从 0 重新开始。【文件核对：`docs/protocol.md` 第 4.1 / 9 节 + 任务书第 4 节】

### 失败排查
- 文件没生成：看是否有写权限、路径是否含中文/空格导致的问题、界面有无报错。
- 缺字段 / 缺帧序号：交给电脑端所有者。
- 时间轴看起来"连续跨帧"：这是**错误**，说明帧间空隙被隐藏了。

## 11. 故障速查表

| 现象 | 优先排查顺序 |
| --- | --- |
| **OLED 无显示** | ① 3.3V/GND 是否接反或松动；② SCL/SDA 是否接反（应为 PB8 / PB9）；③ 程序是否真的烧录成功（回阶段 B）；④ 断电重新上电 / 复位；⑤ 软件 I2C 依赖上拉电阻，确认模块板是否自带；⑥ 换一个已知能显示的例程验证 OLED 模块本身好坏【待确认】 |
| **串口找不到 / 端口列表为空** | ① 设备管理器有没有出现 COM 口 → 没有就是驱动问题（CH340 / CP2102 / FT232 装对应驱动）；② 换 USB 线、换 USB 口；③ 模块 3.3V 跳线是否正确；④ 界面点「刷新」重新枚举；⑤ 是否被串口助手 / 别的 Python 进程占用；⑥ 板子是否已上电 |
| **连上但立刻「已断开」** | ① GND 是否共地；② TX/RX 是否接反；③ 波特率是否 115200 8N1；④ 是否有别的程序占用 COM 口 |
| **波形是一条直线** | ① 是否还在「模拟数据」的直流模式（误认）；② 是否点了「暂停」或「单次」被冻结；③ 电位器滑动端是否真接到 PA0、是否在转；④ 触发阈值是否设太高导致「等待触发/未触发」；⑤ 是否「帧不更新」（见下一条） |
| **读数贴 0** | ① PA0 是否接到了 GND 或电位器旋到 0 端；② 外部信号源是否与板共地；③ PA0 是否悬空（悬空读数随机，不代表 0 V）；④ 是否用了正确的 `vref_mv` |
| **读数贴 4095** | ① 电位器是否故意旋到 3.3 V 端（那是正常满量程）；② **若不是故意，立刻断电，用万用表量 PA0 对 GND 电压**，确认没有误接 5 V 或更高电压；③ 换算用的 `vref_mv` 是否正确 |
| **帧不更新 / 界面卡住** | ① 是否点了「运行」（START 是否被设备确认）；② 状态栏是否「已断开」/「等待设备」；③ TX/RX 接反导致设备收不到命令；④ 响应帧 SEQ 是否匹配、`status` 是否 OK；⑤ 是否被「暂停 / 单次冻结」锁住；⑥ 状态栏有没有 EVENT（0x22）错误帧（协议错误 / ADC 溢出 / 帧被丢弃 / 帧间隔异常）；⑦ 断开重连、重新上电 |
| **切换采样率没生效** | ① 是否收到匹配 SEQ + status OK + `actual_rate_hz == 请求值`；② 是否在发送中切换（回 `status=0x02` 忙，界面应提示「设备忙，未切换」）；③ 先「停止」再切 |
| **一直「等待触发」** | ① 阈值是否在信号幅度范围内；② 信号是否有上升沿（直流不该触发，属正常）；③ 是否误把「自动」当成触发模式 |
| **立刻断电的红色信号**（任何阶段出现都适用） | 冒烟、异味、芯片/OLED/模块发烫、上电瞬间电脑提示 USB 异常、PA0 量到 >3.3 V 或负电压、电位器旋到端点时 PA0 电压明显不对 |
